# 特征一致性工作台 · Feature Consistency Console

离线批处理与在线服务对同一批特征必须给出同一个答案。这个应用把两者的差异
定位到**具体特征**和**具体输入记录**，修复时**只重算受影响实体**，发布新版本
时提供**灰度与回滚**，并在页面上展示差异样本、版本、灰度范围和验证结果。

零依赖：Node 内置 `http` + `node:sqlite` + 原生 ESM，页面是手写的 DOM 渲染，
没有构建步骤。

## 运行

```bash
npm start          # http://localhost:4173
npm test           # 引擎 / 服务 / HTTP / 无头渲染 共 56 个测试
npm run reset      # 删除 data/fcx.db，下次启动重建基线
npm run dev        # --watch 模式
```

`PORT` 改端口，`FCX_DB` 改数据库路径（`':memory:'` 也可）。

## 领域模型

- **实体**：48 个账户 `ACC-2041..2088`，确定性生成 2176 条事件与 49 行客户维表。
- **特征**：`spend_24h`、`spend_7d`、`txn_count_24h`、`refund_ratio_7d`、`risk_score`。
- **口径（pipeline）**：窗口开闭、去重键、键规范化、水位、维表连接、汇率缺失、
  空金额、无样本填充、bundle 版本 —— 离线与在线各一份配置。
- **注入的边界情况**（`src/seed.js` 的 `INJECTED`，仅用于测试与文档，引擎不读取）：
  窗口起点/终点事件、迟到事件、改单重试、键变体、维表扇出、维表缺失、缺汇率、
  空金额、窗口内无样本。

引擎按实体×侧评估每条原始记录的可见性（迟到 / 键变体 / 去重覆盖 / 维表 / 汇率 /
空值），再按特征窗口聚合。差异归因是**反事实**的：对每个候选原因单独应用修复预设、
重新计算两侧、测量剩余差异下降多少，排序得到主因与贡献，不写死。

## 只重算受影响实体

特征向量按 `(side, entity_key, config_hash)` 物化在 SQLite 里。对比读的是物化结果，
所以「哪些实体被重算、哪些被复用」是可观察的事实而不是日志口径。

修复范围的地面真值是 `entitiesWhoseVectorsChange(fromConfigs, toConfigs)`：把新旧配置
分别跑一遍每个实体，向量变了的才进入范围。这比按原因标志匹配更严格——例如一条迟到
事件同时落在窗口边界上，只按 `late` 标志会漏掉它。每次重算还会校验范围外所有实体
在现配置下能否复现已存向量，`verified.drifted` 必须为空；同一范围再算一次必须得到
相同摘要（幂等探针）。

## 灰度与验证

- 灰度按 `hash(salt:version) % 100 < percent` 对实体分桶，同一发布下每个实体命中稳定。
- 首批和放量只重算「进出灰度组的实体」；灰度组外的物化保持不变。
- 验证（`validateRelease`）用三个检查：
  1. **灰度组差异可解释** —— 每项差异要么基线已有，要么落在 bundle 声明的
     `impact { features, max_abs_delta }` 内，并且把在线版本钉回现役版本后确实消失。
     声明影响面之外的差异 = 回归。
  2. **影响范围** —— 灰度组外没有新增差异。
  3. **迟到与重复处理** —— 新版本不改变任何记录级决策，且重复计算幂等。
- 回滚把在线版本恢复为现役版本，只重算曾进入灰度组的实体，差异数回到基线。

内置 bundle：`3.2.0` 现役；`4.0.0` 草稿（声明影响 `risk_score` ≤ 0.25，验证通过）；
`4.1.0` 草稿（退款权重调高，实际影响超出声明，验证失败——用来演示拦截）。

## 代码结构

```
src/deterministic.js  哈希 / 分桶 / 采样 / 稳定序列化
src/spec.js           特征、原因、修复预设、默认口径、bundle 声明
src/seed.js           确定性世界与注入的边界情况（含测试用 ground truth）
src/engine.js         记录可见性、特征聚合、差异、反事实归因、范围真值
src/store.js          SQLite：物化、发布、修复、事件、快照、重算作业
src/service.js        应用服务：对比、修复规划与执行、灰度、验证、回滚
src/server.js         零依赖 HTTP 服务 + 静态资源 + createApp()（测试用）
public/               页面：dom.js 元素构造、format.js 展示格式、app.js 视图
test/                 node:test（引擎 / 服务 / HTTP / 无头 DOM 渲染）
```

## 测试

```bash
npm test
```

- `test/engine.test.js` —— 基线规模、每种原因的归因、迟到/重复/键变体/边界记录、
  修复范围、九类修复收敛到 0 差异、灰度分桶、放量增量、回滚、验证通过与拦截。
- `test/service.test.js` —— 物化键与陈旧检测、样本证据、质量清单、`validateNow`、
  确定性、重置、state 载荷。
- `test/api.test.js` —— 真实 socket 上的全部路由与错误路径、完整灰度闭环、静态资源与路径穿越。
- `test/render.test.js` —— 用最小 DOM 影子渲染真实 `app.js`：五个视图、筛选、下钻抽屉
  的标记记录、渲染幂等。
